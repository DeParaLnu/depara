# Деплой бекенда (не локально)

> Основний варіант хостингу для команди: власний VPS з Docker, див. [deploy-vps.md](deploy-vps.md).
> Цей документ описує загальні вимоги до змінних середовища та запасний варіант на Render + Neon + Upstash.

Бекенд збирається в Docker-образ (`backend/Dockerfile`). Для роботи потрібні три речі:
сервіс з цим образом, PostgreSQL і Redis. Хостинг може бути будь-який, що вміє запускати
Docker або Node (Render, Railway, Fly.io тощо). Нижче загальні кроки та приклад.

> Стан: Dockerfile перевіряється в CI (job `backend-docker`: збірка, міграції, `/health`).
> Реальний деплой на хостинг ще не виконано, тому приклад нижче треба пройти і виправити під фактичний сервіс.

## Що відбувається при старті контейнера

1. `prisma migrate deploy` застосовує міграції до `DIRECT_URL`.
2. Запускається сервер (`tsx src/server.ts`) на `0.0.0.0` і порту з `PORT` (за замовчуванням 3000).
3. `GET /health` повертає `{"status":"ok"}`.

Якщо міграція не пройшла або немає `JWT_SECRET`, контейнер завершується з помилкою, а не стартує зламаним.

## Змінні середовища

| Змінна | Обов'язкова | Опис |
|---|---|---|
| `DATABASE_URL` | так | Рядок підключення до PostgreSQL для застосунку |
| `DIRECT_URL` | так | Пряме підключення для міграцій. Якщо пулера немає, поставте таке саме значення, як `DATABASE_URL` |
| `REDIS_URL` | так | Redis (`redis://...` або `rediss://...` для TLS, наприклад Upstash) |
| `JWT_SECRET` | так | Випадковий рядок: `openssl rand -hex 32`. Без нього сервер не стартує |
| `PORT` | ні | Хостинг зазвичай задає сам |
| `MICROSOFT_CLIENT_ID` | для входу | Application (client) ID застосунку в Microsoft Entra, він же `aud` ID-токена. Без нього `POST /auth/microsoft` відповідає 503 |
| `MICROSOFT_TENANT_ID` | для входу | Directory (tenant) ID організації, з якої пускаємо (`tid` токена). Токени інших тенантів відхиляються |
| `ALLOWED_EMAIL_DOMAIN` | ні | Домен пошти, який пускаємо. За замовчуванням `lnu.edu.ua` |
| `CORS_ORIGINS` | для веб-адмінки | Origin веб-адмінки через кому, без слеша в кінці. Порожньо = CORS вимкнений (мобільному застосунку він не потрібен) |
| `ADMIN_EMAILS` | для першого адміна | Пошти через кому, які отримують роль ADMIN при вході |

**У проді не задавати `NODE_ENV=test` і `AUTH_MODE=fake`.** Образ сам ставить `NODE_ENV=production`,
а фейковий вхід і демо-консоль (`/dev`) працюють лише в тестовому режимі.
Секрети зберігаються в змінних хостингу, не в репозиторії і не в `.env`, який комітять.

## Приклад: Render + Neon + Upstash

Безкоштовні плани та їхні обмеження змінюються, перевірте їх перед вибором.

1. **PostgreSQL.** Створіть базу (Neon або Supabase) і скопіюйте рядок підключення.
   Для старту використайте один рядок (пряме підключення) і для `DATABASE_URL`, і для `DIRECT_URL`.
   Якщо береться pooler (PgBouncer), додайте до `DATABASE_URL` параметр `?pgbouncer=true`, а `DIRECT_URL` лишіть прямим.
2. **Redis.** Створіть базу в Upstash і скопіюйте `rediss://...` у `REDIS_URL`.
3. **Сервіс.** У Render: New → Web Service → підключити репозиторій, середовище Docker,
   Root Directory `backend`, Health Check Path `/health`.
4. **Змінні.** Додайте змінні з таблиці вище. `JWT_SECRET` згенеруйте локально.
5. **Деплой.** Після першого запуску відкрийте `https://<сервіс>/health`.
6. **Перший адмін.** Додайте свою пошту в `ADMIN_EMAILS` і увійдіть. Далі ролі змінює `PATCH /admin/users/:id/role`.
7. **Розклад.** Імпортуйте його через `POST /admin/schedule/import` з токеном адміна (формат описано в README).

## Мобільний застосунок

У збірці застосунку змінна `API_URL` має вказувати на публічну **HTTPS**-адресу сервісу:
Android не дозволяє звичайний HTTP у збірках без спеціального дозволу.

## Локальна перевірка образу

```bash
docker compose up -d                       # Postgres і Redis
docker build -t depara-backend backend
docker run --rm --network host \
  -e DATABASE_URL=postgresql://postgres:postgres@localhost:5432/depara \
  -e DIRECT_URL=postgresql://postgres:postgres@localhost:5432/depara \
  -e REDIS_URL=redis://localhost:6379 \
  -e JWT_SECRET=local-secret \
  depara-backend
curl http://localhost:3000/health
```

## Відомі обмеження

- Бекенд запускається через `tsx` без попередньої компіляції, тому в образі лежать dev-залежності. Образ більший, ніж міг би бути. Перехід на збірку в `dist/` можливий пізніше.
- Домен пошти `lnu.edu.ua` поки зашитий у `config.ts`. Для власного тенанта Entra його треба зробити змінною (задача входу через Microsoft).
- Міграції виконуються при кожному старті. Для одного екземпляра це нормально; при кількох краще окремий крок релізу.

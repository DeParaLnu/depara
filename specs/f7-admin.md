# F7. Адмінка: ролі та імпорт розкладу

**Стан:** бекенд є (включно з призначенням групи і CORS), веб-сторінка адміна в плані · **Відповідальні:** бекенд, мобільний/веб, дизайн

## Навіщо
Адміністратор призначає старост і завантажує розклад, а студенти цього не бачать.

## Хто користується
Лише адмін. Перших адмінів задає змінна `ADMIN_EMAILS`.

## Як це працює
- **Ролі:** адмін бачить користувачів (пошук) і змінює роль: студент, староста, адмін. Змінити власну роль не можна.
- **Група користувача:** адмін призначає групу й підгрупу будь-якому користувачу (наприклад, старості, який ще не пройшов онбординг). Без підгрупи ставиться `0` (бачити всі).
- **Імпорт розкладу:** завантаження JSON або CSV. Імпорт «все або нічого»: якщо в файлі є помилки, не зберігається нічого, а відповідь містить список помилок.
- **Вхід адміна:** окрема веб-сторінка з тим самим провайдером входу (Microsoft). Для неї бекенд вмикає CORS для origin зі змінної `CORS_ORIGINS` (через кому); порожня змінна = CORS вимкнений. Дозволені методи GET/POST/PATCH/DELETE, заголовки `Authorization`, `Content-Type`; cookie не використовуються.
- На макеті мобільного застосунку адмін-панель позначена як V1.1: в MVP імпорт іде через CLI і захищений API.

## API
| Метод і шлях | Для чого |
|---|---|
| `GET /admin/users` | Пошук і список користувачів |
| `PATCH /admin/users/:id/role` | Змінити роль |
| `PATCH /admin/users/:id/group` | Призначити групу (`groupId`) і підгрупу (`subgroup` 0–2, за замовчуванням 0) |
| `POST /admin/schedule/import` | Імпорт розкладу (JSON або CSV) |

Помилки: `INVALID_ROLE`, `CANNOT_CHANGE_OWN_ROLE`, `USER_NOT_FOUND`, `GROUP_REQUIRED`, `INVALID_GROUP_ID`, `INVALID_SUBGROUP`, `GROUP_NOT_FOUND`, `INVALID_IMPORT` (422), `FORBIDDEN` (403).

## Критерії приймання
- [ ] Не-адмін отримує 403 на всі `/admin/*`.
- [ ] Адмін призначає старосту, і той одразу отримує права (роль читається з бази на кожен запит).
- [ ] Адмін призначає групу користувачу, і той одразу бачить її розклад; невідомий користувач або група дають 404, некоректна підгрупа 400.
- [ ] Preflight `OPTIONS` з дозволеного origin проходить (PATCH, `Authorization`), з чужого origin відповідь не містить `Access-Control-Allow-Origin`.
- [ ] Некоректний файл імпорту дає 422 зі списком помилок і нічого не змінює.
- [ ] Коректний файл додає пари; повторний імпорт оновлює їх, а не дублює.
- [ ] Дубль пари всередині файлу дає 422 з поясненням.

## Відкриті питання
- Адмін-панель в застосунку чи тільки у вебі (рішення за техлідом).

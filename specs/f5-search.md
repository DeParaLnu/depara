# F5. Пошук аудиторій і викладачів

**Стан:** бекенд і екран «Аудиторії» готові; пошук викладачів відкладено до V2 · **Відповідальні:** мобільний, бекенд, дизайн

## Навіщо
Швидко знайти, де аудиторія, і в якому вона корпусі.

## Як це працює
- Поле пошуку на екрані «Аудиторії» («Пошук аудиторії чи корпусу»), фільтри-чіпи за корпусом.
- Запит шукає одночасно аудиторії (на бекенді, `GET /classrooms?q=`) і корпуси (на клієнті, серед `GET /buildings`).
- Корпус підходить під запит, якщо:
  - запит з однієї літери збігається з літерою корпусу (`т` → корпус Т; латинська `T` теж). Одна літера не шукається в назві й адресі, інакше `т` знаходила б майже всі корпуси;
  - довший запит є частиною літери, назви або адреси (`тарнав` → корпус Т, `університетська` → Головний).
- Обраний чіп звужує і аудиторії, і корпуси.
- Результат: аудиторія з корпусом і адресою; корпус з назвою й адресою. Тап по будь-якому з них прокладає маршрут у картах до адреси корпусу (у запиті лише адреса і «Львів», без назви корпусу й номера аудиторії, яких Google Maps не знає).
- Без запиту показується список корпусів.
- Нічого не знайдено ні серед аудиторій, ні серед корпусів: стан «Нічого не знайдено» з підказкою, що можна шукати.
- Пошук нечутливий до регістру, максимум 20 аудиторій.
- Запит нормалізується так само, як імпорт (`normalizeRoom`): без пробілів, `№`, `n` і кирилична `Н` на початку стають `N`. Запит `218/Т` шукає за номером і корпусом, латинська `T` у корпусі теж підходить.

## API
| Метод і шлях | Для чого |
|---|---|
| `GET /classrooms?q=&building=` | Аудиторії за частиною номера або за `номер/корпус` (`q`) і/або корпусом (`building` = літера корпусу, регістр не важливий). Невідомий корпус дає порожній список |
| `GET /buildings` | Довідник усіх корпусів (`code`, `name`, `address`), за літерою. Для чіпів-фільтрів і блоку «Корпуси» |
| `GET /teachers?q=` | Викладачі за частиною імені. У MVP застосунок використовує його лише у формі заміни (F6) |

Повторений параметр (`building` або `q` двічі) дає `400 INVALID_QUERY`.

Аудиторія повертається як `id`, `number`, `label` (`номер/корпус`), `building` (`code`, `name`, `address`). Той самий об'єкт `room` і `newRoom` у `GET /schedule/week`.

## Критерії приймання
- [ ] Запит `N1` повертає аудиторії, номер яких містить `N1`, не більше 20.
- [ ] Регістр запиту не впливає на результат.
- [ ] Запити `№9`, `n9` і `Н9` знаходять `N9/Б`; `218/Т`, `218/т` і `218/T` знаходять `218/Т`.
- [ ] Порожній запит повертає список без помилки.
- [ ] Для кожної аудиторії видно корпус і його адресу.
- [ ] `GET /buildings` повертає всі корпуси з адресою, лише для авторизованих.
- [ ] `building=Т` повертає лише аудиторії корпусу Т; разом з `q` фільтри діють одночасно.
- [ ] Запит із літерою (`г`) або частиною назви чи адреси корпусу (`тарнав`) показує відповідний корпус, і лише його.
- [ ] Для знайденого корпусу доступний маршрут.
- [ ] Запит без збігів показує зрозумілий порожній стан, а не помилку.

## Рішення
- Окремий пошук викладачів у MVP не робимо (04.11.2026): `GET /teachers` віддає лише імʼя й посаду, без кабінету, кафедри й розкладу, тож список імен студенту майже нічого не дає. Макета теж немає. Повернемося разом із розкладом викладачів (див. [v2-backlog.md](v2-backlog.md)).
